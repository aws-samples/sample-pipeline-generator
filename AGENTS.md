# AGENTS.md

GenAI-tool-agnostic guide for authoring, planning, and deploying pipelines in this repository. Read by Codex, Cursor, Aider, and (via [`CLAUDE.md`](CLAUDE.md)) Claude Code.

Keep it as a recipe, not a design doc. If you need background, follow the pointers.

## What this repo is

A platform for defining Step Functions data pipelines declaratively. A pipeline is a `pipeline.yaml` plus per-step `code/`. Everything else — Batch, Lambda, ECR, S3, IAM, Step Functions — is generated by shared OpenTofu modules.

Your job as an agent: copy a working example, edit `pipeline.yaml` and step code, then run the existing Make targets. Do not write orchestration OpenTofu from scratch.

## Recipe: create a new pipeline from scratch

1. **Copy the canonical example.**
   ```bash
   cp -R examples/end-to-end examples/<new-name>
   ```
   `<new-name>` MUST be S3-safe: lowercase letters, digits, hyphens only. It becomes an S3 bucket prefix — `tofu apply` fails with `InvalidBucketName` otherwise.

2. **Rewrite `examples/<new-name>/pipeline.yaml`.** Set `pipeline_name: <new-name>` (must match the directory), edit `buckets`, `tags`, `steps`. Validate against the JSON Schema — see [Validate before writing](#validate-before-writing).
   - Step `name` values use underscores only (no hyphens). Each becomes an ECR repo suffix, a Step Functions state, and a `code/<step>/` directory.
   - At most one step may have `type: parallel`.
   - `intermediate` bucket is mandatory. Add `source` / `output` if the pipeline reads/writes them.
   - Full field reference: [`infra/modules/pipeline/schemas/README.md`](infra/modules/pipeline/schemas/README.md).

3. **Reconcile step code.** Ensure `examples/<new-name>/code/<step>/` exists for every `batch`/`lambda` step (no directory for `parallel` blocks themselves — only for their nested steps).
   ```bash
   ./examples/scaffold.py reconcile <new-name>
   ```
   Or copy sibling steps from `examples/end-to-end/code/` manually and edit `main.py`, `pyproject.toml`, `Dockerfile` (batch only).

4. **Fill the env config.** Copy `env/dev/inputs.tfvars.example` and `env/dev/backend.tfvars.example` to real files (they are gitignored). Set `region`, `vpc_id`, `subnet_ids`, and a unique state `key` (convention: `tf-<new-name>.tfstate`).

5. **Plan and deploy** — see [Build, plan, deploy](#build-plan-deploy).

## Validate before writing

Before writing `pipeline.yaml` or `inputs.tfvars`, validate the shape against the JSON Schema at [`infra/modules/pipeline/pipeline-spec.schema.json`](infra/modules/pipeline/pipeline-spec.schema.json). The schema is derived from `infra/modules/pipeline/variables.tf` and covers step types, required fields, defaults, and validations (e.g. hyphens in step names, missing `intermediate` bucket, unknown step type, two parallel blocks, `custom` fan-out without `field`).

```bash
# CLI (installed via pre-commit or pipx install check-jsonschema==0.30.0)
check-jsonschema \
  --schemafile infra/modules/pipeline/pipeline-spec.schema.json \
  path/to/generated-spec.json
```

Or in Python:

```python
import json, jsonschema
schema = json.load(open("infra/modules/pipeline/pipeline-spec.schema.json"))
jsonschema.Draft202012Validator(schema).validate(spec)
```

The `pipeline.yaml` on-disk shape is separately validated by pre-commit against [`infra/modules/pipeline/schemas/pipeline.schema.json`](infra/modules/pipeline/schemas/pipeline.schema.json) (same step types, but covering YAML-only fields such as `pipeline_name`, `buckets`, `ssm_parameters`, and `secrets`).

## Build, plan, deploy

All targets are already defined — do not reinvent them.

### One-time per AWS account: bootstrap + shared image

`account-setup` provisions its own OpenTofu state backend, so a fresh account requires a **two-pass** first run before you can use `make all`:

```bash
# Requires AWS_ACCOUNT_ID, AWS_REGION exported (or in a .env file)

# Pass 1 — backend "s3" {} is commented out in
# infra/deployments/account-setup/terraform.tf (ships that way). Creates
# the state bucket + KMS CMK + IAM + VPC + ECR with local state.
make -C infra/deployments deploy-account-setup

# Uncomment `backend "s3" {}` in account-setup/terraform.tf.

# Pass 2 — OpenTofu prompts to migrate local state into the S3 bucket.
# Answer "yes".
make -C infra/deployments deploy-account-setup

# From here on state lives remotely and `make all` is the steady-state path.
make -C infra/deployments deploy-shared
```

Once the two-pass bootstrap is done, `make -C infra/deployments all` runs `deploy-account-setup` + `deploy-shared`. Sub-targets: `deploy-account-setup`, `deploy-shared`, `unit-tests-shared`, `build-shared`, `push-shared`, `update-parameter-store-shared`.

### Per-pipeline: plan / apply / build images

```bash
# Plan (also runs tofu-init)
make tofu-plan DEPLOYMENT=<new-name>

# Plan + Checkov + apply
make tofu-apply DEPLOYMENT=<new-name>

# Build + push + register a single step image
make deploy-image DIR=<new-name>/code/<step>

# Build + push + register every step image in the deployment
make deploy-all-images DEPLOYMENT=<new-name>

# Full deploy: infra apply + all images
make deploy DEPLOYMENT=<new-name>

# Teardown (also runs tofu-init)
make tofu-destroy DEPLOYMENT=<new-name>
```

Overridable variables: `ENVIRONMENT` (default `dev`), `IMAGE_TAG` (default: read from `pyproject.toml`), `CONTAINER_RUNTIME` (default `docker`; `finch`, `podman` also work).

Every target name here is confirmed against `Makefile` and `infra/deployments/Makefile`. Diff with `grep -E '^[a-zA-Z_-]+:' Makefile infra/deployments/Makefile` if you suspect drift.

## Guardrails you MUST obey

- **OpenTofu, not Terraform.** Every command uses `tofu`. Never emit `terraform apply`. Provider constraint: OpenTofu `>= 1.8`.
- **Conventional Commits.** `feat(scope): …`, `fix(scope): …`, `docs(scope): …`, `test(scope): …`, `refactor(scope): …`, `ci(scope): …`. Scope = module or pipeline name when relevant. Enforced by `gitlint` on `commit-msg`.
- **Never `git push` without explicit user consent.** Commit locally; wait to be asked.
- **Stage explicitly.** `git add <files>`, never `git add .` — the repo intentionally gitignores `.tfvars`, `.env`, `.claude/`, and `poetry.lock`. Blind staging risks leaking secrets or dropping unrelated changes into the commit.
- **Per-module completion contract.** A change to a Terraform module is done only when (1) module code, (2) tests in `iac_tests/main.tftest.hcl`, and (3) the module `README.md` are all updated. A Python change is done only when unit tests and the step's `README.md` are updated.
- **Security scanners.** Run before declaring done:
  - Terraform: `make checkov-modules` (or `make checkov-check DEPLOYMENT=<name>` for a single pipeline plan, `make checkov-all` for both).
  - Python (non-test): `bandit -c .bandit -r <path>`.
  - GitHub workflows: `actionlint <path>`.
  - Fix every finding, or suppress with a rule ID + written justification.
- **Pre-commit hooks are the ground truth.** Run `make pre-commit-checks` (equivalently `pre-commit run --all-files`) before requesting a commit. Never `--no-verify`.
- **Repo-wide gate.** `make verify` chains `check-locks`, `unit-tests-all`, `checkov-modules`, and `pre-commit-checks` and needs no AWS credentials — run it before declaring a multi-file change done. `make integration-tests` covers the deployed-pipeline suites and does need credentials.
